# 多端工程结构

> 2026-09-27 建立。桌面版（Windows）与安卓版从此平级，共享业务层单独成包。
> 鸿蒙版将来按同样方式挂在旁边。

## 三个 crate 的职责

| crate | 包名 | 职责 | 平台 |
|---|---|---|---|
| `core` | `worklog-core` | 数据模型 + 排期算法。纯计算，无 IO、无线程、无 UI | 三端共用 |
| `app/src-tauri` | `worklog` | 桌面版全部：命令层、数据库、托盘、提醒轮询 | Windows |
| `android/src-tauri` | `worklog-android` | 安卓版：移动端命令层（待搬） | Android |

**依赖方向是单向的**：`app → core`、`android → core`，`core` 不依赖任何一端。
将来加鸿蒙版就是再挂一个 `harmony/` 指向同一个 `core`。

## `core` 的三条纪律

写在 `core/src/lib.rs` 顶部，加代码前先看：

1. **不得依赖 tauri** —— 否则移动端就搬不动了；
2. **不得读写文件、不得起线程** —— 保持纯函数，单测才跑得动；
3. **需要「现在几点」的地方一律由调用方传进来** —— 不在里面取系统时钟。

第 3 条不是洁癖：排期结果是「按当前时刻算下一次」，一旦内部取时钟，单测就只能靠
真实时间，那些跨月、跨季、闰年的边界用例根本没法稳定复现。现在 `next_from(rule, from)`
的 `from` 是实参，23 个用例才能把 2 月 30 日、季度锚点这些东西钉死。

**排期算法三端一致是纪律**：各端各写一遍，迟早出现同一个周期任务在不同端算出不同日期，
用户根本不会想到是端的问题。三端共用 `core`，这条纪律才落得下来。

## 为什么用 workspace

主要是**一份 `Cargo.lock`**。桌面版和安卓版必须钉在完全相同的依赖版本上，
各建各的锁文件迟早会出现「同一份数据两端行为不同」——和排期算法必须一致是同一类问题。

`default-members` 只列 `core` + `app/src-tauri`：日常 `cargo test` 只编桌面版（快），
安卓端编得慢且多数改动与它无关，要验时显式写 `cargo test --workspace`。

## ⚠️ 三个坑（都实际踩过）

### 1. `[profile.release]` 必须写在工作区根

写在成员 crate 的 `Cargo.toml` 里 **cargo 会直接忽略**，只给一行很容易看漏的 warning：

```
warning: profiles for the non root package will be ignored
package:   app\src-tauri\Cargo.toml
workspace: Cargo.toml
```

本项目交付体积全靠 `opt-level="z"` + `lto` + `strip` + `panic="abort"` 这一组设置。
漏掉的后果：exe 大一圈、panic 行为变回 unwind —— **都不报错**，只是交付物悄悄变了。

### 2. 不要移动 `target/` 目录

把 `app/src-tauri/target` 挪到工作区根之后，构建直接失败：

```
failed to read plugin permissions: failed to read file
'...\app\src-tauri\target\debug\build\tauri-005d8f74aaacbb45\out\permissions\...'
系统找不到指定的路径。 (os error 3)
```

根因不是工作区不兼容，而是**构建脚本的缓存输出里焊死了绝对路径**：`tauri` 的构建脚本
把权限文件路径写进缓存，cargo 认为它仍是新鲜的，就直接重放了带旧路径的记录。
搬完 target 后必须 `cargo clean` 重编，缓存救不回来。建工作区时一次性付清这个代价。

### 3. 中文路径对安卓构建的影响 —— **尚未验证**

仓库根是 `C:\Users\Lenovo\Desktop\工作记录本\`，中文。桌面版一路用下来没问题，
但安卓的 Gradle + NDK 对非 ASCII 路径的容忍度还没实测。若失败，退路是建 junction
或把工程移到英文路径（GitHub 仓库已叫 `WorkLuLu`，方向一致）。

另外顺带一提：`tauri` 把前端资源嵌进二进制时会临时写一个内容寻址的 `.html` 到
`target/.../tauri-codegen-assets/`。这台机器上偶发 `拒绝访问 (os error 5)`，
看着像安全软件短暂锁住了刚写入的文件 —— **直接重试即可**，不是代码问题。

## 验证命令（改了结构后）

```bash
# 桌面版：默认只编 core + app，快
cargo test                                  # 62 项（worklog 39 + core 23）

# 安卓版一起编（慢）
cargo test --workspace

# 前端（路径没变，还在 app/ 下）
cd app
node --check ui/assets/app.js
node tools/check_ui.js                      # 122 项
node tools/check_stats.js                   # 8 项
node tools/check_contract.js                # 四类契约差集

# 桌面交付物
cargo build --release -p worklog
```

**测试数量的口径变了**：以前 `cd app/src-tauri && cargo test` 是 62 项，现在
schedule 的 23 项在 `core` 里。要么在仓库根跑 `cargo test`，要么记住这个拆分。

## 安卓工程现状

**骨架阶段**：目标是打通编译链路，不是功能完整。

- ✅ `lib.rs` 移动端入口、`Cargo.toml`（`staticlib`/`cdylib`/`rlib`）、`tauri.conf.json`
- ✅ `capabilities/default.json` 只放 `core:default`（托盘、自启动、对话框都是桌面专属）
- ✅ 两个命令 `describe_schedule` / `next_occurrence`，**整条链路走 `worklog_core`**——
  存在的意义就是证明共享层在安卓上真的能跑
- ⬜ 数据层（`db.rs` + `commands.rs` 约 2000 行）尚未搬过来
- ⬜ 前端要做触屏适配（桌面版 34 处 `:hover`、0 处 `@media`，直接搬过去点不动）
- ⬜ 提醒机制整个重做（现在是 `std::thread::spawn` + `sleep(30s)`，安卓上进程被回收后
  线程静默消失）

`android/ui/index.html` 是**临时的骨架自检页**，等真界面做好后就删掉。
它不复用 `app/ui` 是有意的：桌面前端是 1120px 鼠标布局，直接搬过来只会看到一堆点不动的
控件，反而分不清是「后端没通」还是「布局不对」。
