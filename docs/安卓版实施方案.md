> 前置阅读：`docs/安卓版可行性研究.md`（立项判断）、`docs/安卓环境搭建记录.md`（环境配方）

## 一、现状核查（以下数字都是实测的，不是估的）

### 代码规模

| 模块 | 行数 | 安卓要吗 |
|---|---:|---|
| `core/`（共享层：模型 + 排期引擎） | 542 | ✅ 已经在用 |
| `app/src-tauri/commands.rs`（数据层） | 2,604 | ✅ **要，但卡在桌面端里** |
| `app/src-tauri/db.rs`（建表 / 迁移 / 便携） | 554 | 🟡 一半要 |
| `app/src-tauri/main.rs`（启动 / 托盘 / 后台线程） | 615 | ❌ 桌面专属 |
| `app/src-tauri/edge.rs` `snap.rs` `win32.rs` `single.rs` `geom.rs` | 1,953 | ❌ **一行都不要** |
| `app/src-tauri/notify.rs` | 102 | ❌ 桌面专属 |
| `app/ui/`（前端） | 4,731 | 🟡 逻辑可借，**版式必须重写** |
| `android/`（现有安卓端） | **170** | — 骨架 |

一句话：**桌面端 5,878 行后端里，只有约 2,700 行是安卓真正需要的，而这 2,700 行现在锁在 `app/src-tauri` 里拿不出来。**

### 36 个后端命令的构成

- **27 个是纯数据操作**（分类 5 + 任务 10 + 完成记录 2 + 模板 4 + 设置 2 + 附件 4）—— 只依赖 `&Connection`，**可以原样复用**
- **9 个是平台相关的**（便携模式、资源管理器、WebView2 重置、文件对话框备份/恢复/导出 CSV、系统程序打开附件、版本号、数据路径）—— 安卓要么删、要么换实现

关键发现：`commands.rs` 里已经有 **12 个接收 `&Connection` 的自由函数**，命令本身只是薄包装（`state.db.lock()` → 调自由函数）。这是当初为了写单测做的抽取，**顺带把数据层做成了可搬的形状**。

### ⚠️ 两个必须知道的外部变化

**1. 安卓构建环境已经没了。** 实测：


## 二、结论

**能做，但不是「把桌面端搬过去」那么简单，也不是「从零重写」那么贵。**

三个判断：

1. **数据层已经是可搬的，代价主要在「搬家」而不是「重写」。** 27 个命令的逻辑一行都不用重写，缺的只是一个不依赖 tauri 的落点。
2. **真正的工作量在前端。** 4,731 行前端是 1120px 三栏 + 鼠标 hover + 拖拽的桌面版式，手机上点不动。按「只实现功能」的要求，这部分是**重写一个精简版**，而不是移植。
3. **有一个前置重构绕不开。** 不先把数据层从 `app/src-tauri` 里抽出来，安卓端就只能复制一份 —— 那就直接违反了项目自己立的规矩（「同一份数据两端行为不同」和「排期算法三端一致」是同一个道理）。

## 三、架构方案

### 3.1 新建 `data/` workspace 成员

```
F:/工作记录本/
├── core/                  # 纯计算（模型 + 排期引擎）      —— 已有
├── data/                  # ★ 新增：纯数据访问（SQLite）    —— 本方案
├── app/src-tauri/         # 桌面端：薄包装命令 + 窗口行为
└── android/src-tauri/     # 安卓端：薄包装命令 + 平台适配
```

**为什么不塞进 `core/`：** `core` 的三条铁律是「不依赖 tauri、不读写文件/不起线程、不取系统时钟」。`db.rs` 用了 `tauri::Manager` 和文件路径，`commands.rs` 用了 `tauri::State` —— 塞进去就破了铁律，而且那些铁律是排期引擎能三端一致、能单测的**根本原因**，不能为了图省事破坏。

**为什么不复制一份到 `android/`：** 复制的那一刻起，两端的「完成任务时怎么算下一次」「应用模板时日期怎么偏移」就开始各自漂移。这类 bug 用户根本不会怀疑是端的问题，极难定位。项目当初把 `Rule` 从 `commands.rs` 搬进 `core` 就是为了这个，没理由在数据层再犯一次。

**`data/` 的纪律（比 core 松一档，但同样要写进文件头）：**

1. **不依赖 tauri** —— 只依赖 `rusqlite` + `worklog-core` + `serde` + `chrono`
2. **不碰文件路径** —— 「数据库放哪」是各端的事（桌面有便携模式，安卓是沙盒私有目录），`data` 只收 `&Connection`
3. **不取系统时钟** —— 需要「现在」的地方由调用方传入（和 `core` 同一条规矩）

### 3.2 落地后的形状

```rust
// data/src/lib.rs
pub mod schema;       // SCHEMA 常量 + migrate + seed + setting_on
pub mod model;        // Task / Category / Completion / Template / Attachment / Progress
pub mod categories;   // 5 个自由函数
pub mod tasks;        // 10 个（含 top_level_tasks / record_occurrence / duplicate_inner）
pub mod templates;    // 4 个（含 template_from_task / apply_inner）
pub mod attachments;  // 4 个
```

两端各自只写薄包装：

```rust
// app/src-tauri/src/commands.rs
#[tauri::command]
pub fn create_task(state: State<'_, AppState>, task: Task) -> R<Task> {
    let conn = state.db.lock().map_err(e2s)?;
    worklog_data::tasks::create(&conn, task)     // ← 逻辑在共享层
}
```

```rust
// android/src-tauri/src/commands.rs
#[tauri::command]
pub fn create_task(state: State<'_, AppState>, task: Task) -> R<Task> {
    let conn = state.db.lock().map_err(e2s)?;
    worklog_data::tasks::create(&conn, task)     // ← 同一份实现
}
```

**关键：桌面端现有代码的调用路径尽量不变。** 在 `app/src-tauri` 里保留一层 `pub use worklog_data::...` 重导出，让 `main.rs`、`check_contract.js` 不用改 —— 和当初搬 `Rule` 时用的是同一个手法。

### 3.3 依赖关系

```
core  ←── data  ←── app/src-tauri
  ↑         ↑
  └─────────┴────── android/src-tauri
```

`Cargo.lock` 仍然只有一份（workspace 根），两端钉在同一批依赖版本上。

## 五、安卓端特有的五个真问题

这五个是方案能不能落地的关键，不是细节。

### 5.1 数据库在私有目录里，用户看不见也拿不走

安卓上 `app.path().data_dir()` 落在 `/data/data/com.local.worklog/`，**普通文件管理器访问不到**。

**对策：**

- **便携模式整块删掉。** 那是给 U 盘设计的，安卓上不存在这个概念。
- 备份/恢复是用户唯一能拿到数据的路径，**必须走 SAF**，而且这不是可选功能 —— 换手机时没有它，数据就是死在里面了。

### 5.2 `content://` URI 是这次最大的技术坑

Tauri 官方文档明确写着：

> The file dialog APIs returns file system paths on Linux, Windows and macOS. On iOS, a `file://<path>` URIs are returned. **On Android, content URIs are returned.**

而 `rusqlite::Connection::open()` **只认文件系统路径，打不开 `content://`**。所以备份/恢复不能「选完路径直接开」，必须中转：

```
【导出】
  私有目录 worklog.db
    → VACUUM INTO 私有目录/backup-tmp.db      （纯 SQLite，两端同一套）
    → 用 tauri-plugin-fs 把 backup-tmp.db 写到用户选的 content:// URI
    → 删临时文件

【导入】
  用户选的 content:// URI
    → 用 tauri-plugin-fs 读进 私有目录/restore-tmp.db
    → 打开校验（能不能读、有没有 tasks 表、schema 版本对不对）
    → 通过才覆盖
```

好消息是 `tauri-plugin-fs` 官方说「works with any path format out of the box」，`content://` 它认。**这一条要在阶段 4 一开始就单独验证，不要留到最后。**

另外 `tauri-plugin-dialog` 在安卓上**不支持文件夹选择器**（官方标注），所以导出只能让用户选文件，不能选目录。

### 5.3 附件走 base64，20 MB 上限在手机上会爆

桌面端附件是「读文件 → base64 → JSON 传给 Rust」，`MAX_ATTACHMENT_BYTES = 20 MB`。手机拍一张照片 3–8 MB，base64 膨胀 33%，再加上 WebView 桥接的字符串拷贝 —— 20 MB 的附件在低端机上会直接 OOM。

**对策（第一版）：**

- 安卓端上限降到 **5 MB**，并在前端做等比压缩（桌面端已经有 canvas 压缩那套逻辑，可以复用）
- 只支持**图片**（拍照 / 相册），PDF 之类先不做 —— 手机上的主要场景就是拍凭证
- 拍照走 `tauri-plugin-barcode-scanner`？不用。走 `<input type="file" accept="image/*" capture="environment">`，WebView 原生支持，**零插件成本**

### 5.4 提醒功能：第一版不做

桌面端靠 `std::thread::spawn` + `sleep(30s)` 轮询。安卓上进程随时被回收，**线程跟着消失而且不报任何错**（这是 `android/src-tauri/src/lib.rs` 里已经写下的结论）。

真要做只能上 WorkManager / 精确闹钟，要申请 `POST_NOTIFICATIONS` + `SCHEDULE_EXACT_ALARM` + 电池优化白名单三个权限，**而且仍然会被国产 ROM 的省电策略干掉**。投入产出比是全项目最差的一块。

**第一版替代方案：** 打开 App 时算一遍「今天有几条到期」，显示在启动页和图标角标上。够用，零权限。

### 5.5 前端必须重写版式

4,731 行前端里，主要渲染函数只占 1,124 行，其余 2,572 行是状态、事件、工具函数 —— **逻辑可以大量借用，版式必须重写**。

| 桌面版式 | 安卓要改成 |
|---|---|
| 1120px 三栏（侧栏 / 内容 / 抽屉） | 单栏 + 底部导航（今天 / 全部 / 已完成 / 我的） |
| 右侧抽屉（详情） | 全屏页，右滑返回 |
| 鼠标 hover 显示操作按钮 | 常显 + 长按菜单（**手机上永远没有 hover**） |
| 拖拽排序 | 长按拖动，或直接砍掉 |
| 窗口控制按钮 / 贴边隐藏 / `data-tauri-drag-region` | 全删 |
| 触控目标偏小 | 所有可点区域 ≥ 44×44 px |
| 安全区 | `env(safe-area-inset-*)` 处理刘海和手势条 |

`style.css` 那 964 行基本不能复用 —— 建议安卓端**另写一份移动优先的样式**，不要试图在桌面样式上打补丁。

## 六、第一版（0.2.0）功能范围

按「只实现功能」的要求，我建议第一版就定位成 **「手机上的查看 + 勾选 + 快速新建」**，把周期性记录这件事在手机上闭环，不追求功能对齐桌面版。

### 做

- [x] 今天 / 全部 / 已完成 三个列表
- [x] 分类筛选
- [x] 新建 / 编辑 / 删除任务
- [x] 勾选完成 —— **周期任务完成后自动滚到下一次**（这是产品的核心，不能少）
- [x] 子任务（模板产生的那些）的勾选与进度
- [x] 模板：只做「应用模板」，不做模板编辑
- [x] 附件：拍照 + 相册选图，5 MB 上限，自动压缩
- [x] **本地备份导出 / 导入（SAF）** —— 这一条是**数据安全**，不是数据交互，见下方说明

### 不做（留 0.3.0 或永远不做）

- [ ] 提醒推送（理由见 5.4，投入产出比最差）
- [ ] 日历视图、统计视图、看板视图（桌面端 265 行，手机上信息密度不够，价值低）
- [ ] 模板编辑器（手机上编多层级结构太痛苦）
- [ ] 便携模式（概念不成立）
- [ ] **任何跨端同步或互通**（2026-10-08 已定：手机和桌面暂时各记各的）

### 关于「备份导出 / 导入」为什么留着

已定「手机和桌面暂时独立、不需要数据交互」，所以**跨端互通整块不做**。但安卓本地的
导出/导入建议保留，理由是它解决的不是「和桌面交换」，而是三个单机场景：

- **换手机** —— 数据在 app 私有目录里，不导出就带不走
- **卸载重装** —— 安卓卸载会连私有目录一起清掉，数据直接蒸发
- **误删恢复** —— 和桌面版一样需要一份快照兜底

成本也几乎为零：5.2 那个 `content://` 中转逻辑**本来就要写**（`VACUUM INTO` +
`tauri-plugin-fs`），导出只是把它接到「另存为」上，导入接到「打开文件」上，
加起来不到一百行。

如果连这个也不要，那安卓端的数据就是**只进不出**的单向容器，风险请知悉。

## 七、阶段拆分

每个阶段都是**可独立验收**的，做完能停下来。

### 阶段 0 · 重建构建环境

照 `docs/安卓环境搭建记录.md` 的配方重做，注意两点：

- 坑 1（github 不通）**这次不用绕了** —— 实测已通，winget 也许能直接用
- 坑 2（`maven.google.com` 不通）**依然存在** —— Gradle 仓库地址必须改，要么改 `gen/android/build.gradle.kts` + `buildSrc/build.gradle.kts`，要么写 `~/.gradle/init.gradle` 全局替换

产出：`cargo tauri android build` 能把现有骨架打成一个 APK。
规模：**小**（主要是 3.3 GB 下载等待）

### 阶段 1 · 抽出 `data/` crate ★ 风险最高的一步

- 新建 `data/`，把 `db.rs` 的 SCHEMA / migrate / seed / setting_on 搬过去
- 把 `commands.rs` 的 12 个自由函数 + 全部模型搬过去，按域拆成 5 个模块
- 补齐剩余 15 个命令的 `&Connection` 版本（现在它们直接写在命令里，要抽出来）
- 桌面端改成调用 `worklog_data::*`，用 `pub use` 重导出保持路径不变
- **`db.rs` 里便携模式那部分留在桌面端**（安卓不要）

**验收标准：桌面端行为零变化。** `cargo test` 130 项、`check_ui` 177 项、`check_stats` 8 项、`check_contract`、`smoke` 53 项 —— **全部必须绿**。

⚠️ 这一步动的是已经稳定运行的桌面版，是整个方案里唯一可能把现有用户搞坏的地方。建议单独一个提交，做完先发一版 1.6.1 验证，再往下走。

规模：**中**（2,700 行搬家 + 补 15 个函数的抽取，改动机械但量大）

### 阶段 2 · 安卓端接上数据层

- `android/src-tauri` 依赖 `worklog-data`
- 写 27 个薄包装命令
- db 初始化：路径换成安卓私有目录，**便携模式整块不要**
- `AppState` 照搬（`Mutex<Connection>`）
- 清掉骨架页那两个演示命令

产出：能用 Rust 单测跑通增删改查（**在 Windows 上跑，不用真机**）。
规模：**小**（27 个函数都是三行包装）

### 阶段 3 · 安卓前端 ★ 工作量最大的一步

- 另写一份移动优先的 HTML/CSS，不要改桌面那份
- 从 `app.js` 借用：数据调用层、状态管理、日期格式化、附件压缩、周期规则编辑器
- 重写：侧栏 → 底部导航，抽屉 → 全屏页，hover → 常显
- 去掉全部桌面专属交互（拖拽、贴边、窗口控制）

产出：手机上能完整走通「看今天 → 勾掉一条周期任务 → 它滚到下周」。
规模：**大** —— 这一步比阶段 1+2 加起来还大

### 阶段 4 · 安卓专属能力

- **先把 5.2 的 `content://` 中转验证通**，这是本阶段的前置
- 安卓本地备份导出 / 导入（SAF）
- 拍照 + 相册选图（`<input type="file">` 原生，零插件）
- 打开附件走 Intent
- 启动时算「今天到期几条」

跨端导入导出**已砍**（见第八节决定 1），本阶段只做安卓本地的数据兜底。

规模：**中** → 砍掉跨端后降为 **小–中**

### 阶段 5 · 打包与发布

- 生成签名 keystore（**务必单独备份，丢了就没法给已装用户升级**）
- 图标、启动图、应用名、版本号
- 默认只出 `arm64-v8a`（覆盖近五年的手机），需要的话再补 `armv7`

## 八、决定记录

### 1. ✅ 手机和桌面**暂时独立，不做任何数据交互**

跨端同步、手动传 `.db`、云同步 —— **整块不做**。两端各记各的。

  跨端那部分直接删掉
- 第六节「做」清单里保留了**安卓本地的**导出/导入，那是数据安全不是数据交互，
  理由见该节末尾；如果这一条也不要，说一声即可，删起来很快
- 长远看，等两端都想通了再考虑互通也不迟 —— 数据格式本来就是同一个 `.db`，
  将来要接成本不会变高

### 2. ✅ 第一版就砍到第六节那个清单

按「查看 + 勾选 + 快速新建」闭环做。**提醒功能第一版不做**，

### 3. ✅ 阶段 1 做完先发一版桌面版（1.6.1）探路
