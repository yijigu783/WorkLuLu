# 使用反馈核实与优化方案

核实日期：2026-09-27
核实方式：逐条对照源码（未凭印象判断）
涉及版本：v1.0.1 → 实施后为 v1.1.0

---

## 一、先回答那个问题：最多支持多少层级？

**目前是 2 层，而且是硬限制。**

后端 `commands.rs::insert_subtask` 里有一道硬校验：

```rust
if pattern != "stage" {
    return Err("只有阶段性工作可以拆分子任务".into());
}
```

而子任务插入时，类型被写死成 `once`：

```sql
INSERT INTO tasks (..., pattern, ...) VALUES (..., 'once', ...)
```

两者合起来意味着：

| 工作类型 | 能挂子任务吗 | 能拆几层 |
| --- | --- | --- |
| 一次性 | ❌ 不能 | 0 |
| 周期性 | ❌ 不能 | 0 |
| **阶段性** | ✅ 能 | **2 层**（工作本身 + 子任务） |

**这是刻意设计的**（子任务不进主列表、不计入"件数"统计，避免把"一步"算成"一件工作"），但有个副作用：**可发现性很差**。

反馈里那位用户之所以要问"最多几层"，很可能是因为他建的是**一次性**任务 —— 这种情况下界面上**根本看不到任何拆解入口**，自然会以为功能不存在。

> 建议：新建工作时若选了"阶段性"，在表单里直接给一句"保存后可以拆解步骤"。不需要改结构，一句话的事。

## 二、三条反馈逐条核实

### 反馈 1 · 点开任务后，点左侧空白区关不掉 —— 属实

遮罩（`.modal-mask`）目前只被用来控制显隐：

```js
mask.classList.add('open');   // 只负责显示/隐藏
```

**没有绑定任何点击事件。** 关闭路径只有三条：

1. 右上角 X（`data-act="close-drawer"` / `close-modal`）
2. 弹窗底部的「取消」按钮
3. **ESC 键 —— 这个其实已经支持了**（`keydown` 里处理了，且输入框聚焦时会先退出输入）

所以严格说不是"关不掉"，是**只有图标和 ESC 两条路，没有符合直觉的"点外面"**。用户不知道 ESC 是常见情况。

**修复要点**（有两处坑）：

- 必须判断 `ev.target === maskEl` 才关闭。否则点弹窗内部任何位置都会冒泡到遮罩，一点就关，比原来更糟
- 抽屉里有可直接编辑的子任务输入框，关闭前要先调 `flushDrawerDom()` 把未保存内容收回来（这个函数已经存在，接上即可）

### 反馈 2 · 日历双击/右击没反应 —— 属实，而且问题比他说的更大

全项目在 `document` / `body` 上只注册了 `click` 一个代理，**没有 `dblclick`、没有 `contextmenu`**。

但真正的问题是：**日历的空白格子完全不可点。** 目前只有"有任务的格子里那条任务"能点开抽屉（`data-act="open"`）。也就是说：

> "我想在某一天加一件事" —— 这个日历视图里最自然的动作，**做不到**。只能切回列表、点新建、再手动把日期选到那一天。

这才是"浪费了"的实质。

**修复方向**：

- 点空白格子 → 直接新建工作，截止日预填那一天
- 右击格子 → 菜单（新建 / 复制当天全部 / 跳到该日）
- 顺带修一个他没提到的：格子里的**「还有 N 项」点了也没反应**，应该点开看当天全部

### 反馈 3 · 日历不能滚轮翻月 —— 属实

翻月只有 `.cal-bar` 里两个小箭头（`cal-prev` / `cal-next`）。没有任何 `wheel` 监听。

**修复要点**（两个坑）：

- **必须节流**。`wheel` 一秒能触发几十次，不节流会一次翻十几月。建议 250ms 一次
- **和页面滚动冲突**。若日历下方还有内容要滚，滚轮翻月会打架。需要判断是否已到滚动边界再触发

滚轮是"增强"不是"必需"，即便做了也要保留左右按钮。

## 三、模板功能（反馈里最有价值的一条）

### 先定性：他的痛点不是层级，是重复劳动

他自己说得很清楚："第 1 次建立所有层级的 20 个任务和子任务后保存为 1 个模板" —— **20 个条目**。

所以真正要解决的是"同一套结构反复手建"，**不是"层级不够深"**。模板的优先级远高于扩层级。

### 设计要点：模板里不能存绝对日期

这是整个设计最关键的一点。模板如果存"2026-10-08 截止"，下个月调用时就过期了。

必须存**相对偏移**：

| 模板项 | 相对开始 | 相对截止 | 提醒 |
| --- | --- | --- | --- |
| 首页终稿 | +0 天 | +3 天 | 提前 1 天 |
| 产品页终稿 | +3 天 | +6 天 | 提前 1 天 |
| 关于页终稿 | +6 天 | +9 天 | 提前 1 天 |

调用时选一个**基准日**（默认今天），按偏移算出真实日期。

### 两种做法，建议先做轻的

**做法一（轻）· 复制现有工作**

- 在任务抽屉里加一个「复制一份」，把它和**它的所有子任务**一起复制
- 日期按原任务内部的相对间隔整体平移到新基准日
- **不需要新表、不需要新界面**
- 覆盖"这件事我每月/每季都要做一遍"这个主场景

**做法二（重）· 完整模板库**

- 新增 `templates` + `template_items` 两张表，需要数据库迁移
- 新增模板列表界面、"从模板新建"流程
- 优势：模板能脱离原任务独立存在、能积累成库、能跨项目复用

**建议先做做法一。** 理由：主场景用"复制"能解决八成，且不引入表结构和界面的复杂度；用下来觉得不够（想攒模板库、想跨设备），再升级到做法二 —— 数据模型可以平滑接上。

## 四、另外几处我顺手发现的问题

1. **子任务入口的可发现性**（见第一节）—— 一句话提示就能解决
2. **日历「还有 N 项」不可点** —— 见上
3. **日历只认截止日**：跨天的阶段性工作只落在**交期那一天**，中间几天在日历上是空的。这是刻意的（源码注释写明），但对"想看到这段时间在忙什么"的人来说是信息缺失。可考虑给跨天任务画一条淡淡的跨度条
4. **术语门槛**：「阶段性」这个词偏书面，普通用户第一眼不一定反应过来这是"可以拆步骤的那种"。可考虑改为「阶段 / 项目」

## 五、优先级建议

| 优先级 | 项目 | 改动范围 |
| --- | --- | --- |
| **P0** | 点遮罩关闭（弹窗 + 抽屉） | `app.js` 加两处监听 + `target` 判断 |
| **P0** | 日历点空白格新建 | `app.js` 日历渲染加 `data-act` + 处理函数 |
| **P1** | 日历滚轮翻月 | `app.js` 一个监听 + 节流（需测滚动冲突） |
| **P1** | 复制工作（连同子任务） | `commands.rs` 加 1 个命令 + 抽屉加 1 个按钮 |
| **P2** | 日历右击菜单 | `app.js` |
| **P2** | 「还有 N 项」可点 | `app.js` 一处 |
| **P3** | 完整模板库 | 新表 + 迁移 + 新界面 + 3~4 个命令 |
| **P3** | 子任务扩到 3 层 | 递归渲染改造（抽屉、进度统计、删除级联都要跟着改） |

**为什么把"扩层级"排在最后**：它看着是用户的直接诉求，但实际痛点在模板。而且扩层级会牵动抽屉渲染、进度统计 `applySubtaskProgress`、删除级联三处逻辑，改动面比看起来大得多 —— 收益却不如模板。

## 六、几点判断

- **P0 两条是"看起来像 bug"的体验问题**，成本和收益最不成比例 —— 改动都只在前端一个文件里，但直接影响第一印象。打算发布或上架的话，建议先修这两条。
- **两条反馈里有价值的信息**：提反馈的人已经用到了"拆分子任务"这个最深的特性，说明他真的在用，不是随便看一眼。这类用户的后续反馈值得留意。
- **不建议现在动的事儿**：无限层级。真要做，3 层封顶即可 —— 再深对"工作记录"这个场景没有实际意义，只会让拖拽、折叠、缩进全都复杂化。

## 七、实施记录（2026-09-27，v1.1.0）

全部落地。下面是逐项对照，以及**两处核实更正**。

### ⚠️ 核实更正一：弹窗遮罩其实是绑了点击的

本文第二节写"遮罩没有绑定任何点击事件"，**这条是错的**。`app.js` 里一直有这么一段：

```js
if (ev.target.id === 'modal-mask') { state.editing = null; state.catEditing = null; renderModal(); return; }
```

弹窗点外面是能关的。用户说的"关不掉"其实指的是**抽屉**：抽屉是并排布局（`position: absolute` 靠右），根本没有遮罩，点主内容区的空白完全无响应。所以改动点是给抽屉加"点外面关掉"，而不是给遮罩补事件——修法完全不同。

### ⚠️ 核实更正二：还有个方案外的问题，一并修了

加模板表之后，备份 / 恢复的清单里**没有模板表**（原来写死四张表），恢复完模板会静默消失。这个坑是这次改动自己引入的，已修，并加了两个回归用例：备份带模板、恢复 1.0.x 老备份不拒收。

### 新增的回归用例

- Rust：三层拆解 / 第四层被拒 / 数据成环时遍历能停 / 复制保留整棵树 / 复制周期性任务不照搬旧日期 / 模板存偏移不存绝对日期 / 按基准日铺开 / 分类被删仍能建 / 备份带模板 / 老备份不拒收
- 前端自检：110 项（原 74 项）。新增覆盖三层渲染与 `+` 入口的边界、日历格子可点、按日弹窗、跨度条、模板页、侧栏入口、抽屉入口

**总数**：cargo test 62 项、check_ui 110 项、check_stats 8 项，四类契约差集为空。

### 顺带修掉的一个连带 bug

`deleteTask` 之前只清 `parentId === id` 的直接子任务。两层结构下没问题，**一放开到三层就会留孤儿**——第三层挂在一个已经被删的第二层上，界面上再也看不到，却还占着库。改成按子树整棵清。
