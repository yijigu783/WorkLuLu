## 二、⚠️ 这台机器特有的四个网络坑

**这是本文档最重要的部分。四个坑都会让安装/构建"看起来在跑、其实必失败"。**

### 坑 1：`github.com` 完全不通 → winget 装什么都会失败

```
winget install EclipseAdoptium.Temurin.17.JDK
  → InternetOpenUrl() failed. 0x80072efd : unknown error
```

原因有两层：

1. `github.com` 在**本机任何路径下都连不上**（`curl` 直连和走代理都是 `code=000`）。
2. **`winget` 走 WinINet（Windows 系统代理设置），读不到 shell 里的 `http_proxy` 环境变量**，
   所以沙箱代理对它无效。

而 winget 里的包**几乎全部**从 github 下载 → **winget 这条路整条废掉**。

**解法**：绕开 winget，用 `curl` 自己下（curl 认 `http_proxy`）。
JDK 换成 **Microsoft OpenJDK**（走 `aka.ms` → `download.visualstudio.microsoft.com`，**是通的**）：

```bash
curl -L -o jdk.zip "https://aka.ms/download-jdk/microsoft-jdk-17.0.20-windows-x64.zip"
mkdir -p /c/Android/jdk && unzip -q jdk.zip -d /c/Android/jdk
# 解出 jdk-17.0.20+8/
```

### 坑 2：`maven.google.com` 不通 → 安卓构建必卡

这个最隐蔽：**它走代理也不通**（`code=000`），DNS 能解析到 Google 的 IP，但连不上。
而它就是 Gradle 里 `google()` 仓库的地址 —— Android Gradle Plugin（AGP）的唯一来源。

**好消息**：`maven.google.com` 只是 `https://dl.google.com/dl/android/maven2` 的**别名**，
而后者**直连即可访问**（`code=206`）。阿里云镜像 `maven.aliyun.com/repository/google` 也通。

**解法**：改 Gradle 的仓库地址。可选（优先级从高到低）：

```
https://dl.google.com/dl/android/maven2          ← Google 官方内容源，本机可通
https://maven.aliyun.com/repository/google       ← 阿里云镜像
```

代价：`tauri android init` 生成的 `gen/android/build.gradle.kts` 与
`gen/android/buildSrc/build.gradle.kts` 里写的都是 `google()`，**要么直接改这两个文件，
要么写 `~/.gradle/init.gradle` 全局替换**。

### 坑 3：Java 默认不读 `http_proxy`

`sdkmanager`、Gradle 的 JVM **不会**自动使用 shell 里的 `http_proxy`。需要时显式传：

```bash
export JAVA_TOOL_OPTIONS="-Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=<port> \
                          -Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=<port>"
```

**但本机实际上不需要** —— `dl.google.com`、`repo1.maven.org`、`services.gradle.org`、
`static.rust-lang.org` 都是**直连可通**的（实测 `code=206/200`）。只有 github 和
maven.google.com 不通。所以尽量**不要**给 JVM 加代理，避免多一层不确定性。

### 坑 4：Maven 官方源"能通，但慢到不可用"（2026-10-08 新发现）

这个坑比坑 2 更阴 —— **它不报错**。地址换对了、构建能跑起来，然后卡在依赖下载上不动。
现象是 `~/.gradle/.tmp/gradle_download*bin` 这个临时文件 15 分钟只长到 15 MB。

实测同一个 13 MB 的 jar（`com.android.tools.build:gradle:9.3.1`）：

| 源 | 实测速度 |
|---|---|
| `dl.google.com`（直连） | 6,407 KB/s |
| `dl.google.com`（走代理） | 8,322 KB/s |
| `repo1.maven.org`（直连） | 256 KB/s |
| 阿里云 `repository/google` | 4,037 KB/s |
| 阿里云 `repository/central` | 7,269 KB/s |
| **Gradle 自己下的** | **3 ~ 7 KB/s** |

**不是网络慢，是 Gradle 那一路慢。** `netstat` 看它直连的就是
`dl.google.com`（202.101.48.33）和 `repo1.maven.org`（104.18.19.12）的真实 IP，
但连接全是 `CLOSE_WAIT`，疑似被反复掐断重连。根因没查明 —— 也没必要查，
因为 **curl 走镜像能到 4~7 MB/s，让 Gradle 也走镜像就行了**。

**解法**：在每个 `repositories { }` 块**最前面**插入三个阿里云端点
（Gradle 按声明顺序试源，插后面等于没插）。三个端点分工不同，缺一不可：

| 端点 | 顶替谁 | 实测 |
|---|---|---|
| `maven.aliyun.com/repository/google` | `google()` / `dl.google.com` | AGP 9.3.1 / androidx / material 全 200 |
| `maven.aliyun.com/repository/central` | `mavenCentral()` | junit 200 |
| `maven.aliyun.com/repository/gradle-plugin` | `plugins.gradle.org` | kotlin plugin marker 200 |

> ⚠️ **别用 `repository/public` 顶 google 的东西** —— 实测
> `com.google.android.material:material:1.12.0` 在它上面 **404**，它只聚合 central + jcenter。

这一步已沉淀进 `android/tools/fix_gradle.py`（见 7.5）。效果：依赖缓存
`~/.gradle/caches/modules-2` 从 76 MB → 229 MB（90 秒）→ 411 MB（构建结束），
而修复前是 15 分钟纹丝不动。

## 三、安装步骤（照抄即可）

```bash
# 1. JDK（绕开 winget，见坑 1）
curl -L -o jdk.zip "https://aka.ms/download-jdk/microsoft-jdk-17.0.20-windows-x64.zip"
mkdir -p /c/Android/jdk && unzip -q jdk.zip -d /c/Android/jdk

# 2. cmdline-tools（约 130 MB）
mkdir -p /c/Android/Sdk/cmdline-tools && cd /c/Android
curl -L -o clt.zip https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip
unzip -q clt.zip -d /c/Android/Sdk/cmdline-tools
# ⚠️ 必须重命名为 latest/，sdkmanager 认这个结构
mv /c/Android/Sdk/cmdline-tools/cmdline-tools /c/Android/Sdk/cmdline-tools/latest

# 3. SDK 组件（sdkmanager 需要 JAVA_HOME 已设）
export JAVA_HOME="C:/Android/jdk/jdk-17.0.20+8"
SDKM="/c/Android/Sdk/cmdline-tools/latest/bin/sdkmanager.bat"
yes | "$SDKM" --sdk_root="C:/Android/Sdk" --licenses          # 接受许可
"$SDKM" --sdk_root="C:/Android/Sdk" \
  "platform-tools" "platforms;android-35" "build-tools;35.0.0"
"$SDKM" --sdk_root="C:/Android/Sdk" \
  "platforms;android-37.0" "build-tools;37.0.0" "ndk;27.3.13750724"

# 4. Rust 目标 + tauri-cli
rustup target add aarch64-linux-android armv7-linux-androideabi \
                  i686-linux-android x86_64-linux-android
cargo install tauri-cli --version "^2" --locked

# 5. 环境变量（用户级，用 PowerShell 写）
[Environment]::SetEnvironmentVariable("JAVA_HOME",        "C:\Android\jdk\jdk-17.0.20+8", "User")
[Environment]::SetEnvironmentVariable("ANDROID_HOME",     "C:\Android\Sdk",                "User")
[Environment]::SetEnvironmentVariable("ANDROID_SDK_ROOT", "C:\Android\Sdk",                "User")
[Environment]::SetEnvironmentVariable("NDK_HOME",         "C:\Android\Sdk\ndk\27.3.13750724", "User")
[Environment]::SetEnvironmentVariable("ANDROID_NDK_HOME", "C:\Android\Sdk\ndk\27.3.13750724", "User")
```

### ⚠️ 两个版本号陷阱

1. **`platforms;android-37` 不存在**。Google 从 API 36 起改用带小版本的包名，
   实际要装的是 **`platforms;android-37.0`** / `37.1` / `37.2`。
2. tauri-cli 2.12 的模板钉的是 **`compileSdk = 37` / `targetSdk = 37`**，
   所以 android-35 不够用，必须装 37 那一档。

### ⚠️ 这里踩的坑：`cc` crate 在 Windows 上找不到 C 编译器

第一次编译直接失败：

```
cc-rs: failed to find tool "clang.exe": program not found
CC_aarch64-linux-android = None
CC_aarch64_linux_android = None
```

**`cc` crate 在 Windows 上不会从 `NDK_HOME` 自动推断编译器**（那套逻辑是 Linux/macOS 的）。
必须显式指定。在 `ndk-probe/.cargo/config.toml` 里：

```toml
[env]
CC_aarch64_linux_android = 'C:\Android\Sdk\ndk\27.3.13750724\toolchains\llvm\prebuilt\windows-x86_64\bin\aarch64-linux-android21-clang.cmd'
AR_aarch64_linux_android = 'C:\Android\Sdk\ndk\27.3.13750724\toolchains\llvm\prebuilt\windows-x86_64\bin\llvm-ar.exe'

[target.aarch64-linux-android]
linker = 'C:\Android\Sdk\ndk\27.3.13750724\toolchains\llvm\prebuilt\windows-x86_64\bin\aarch64-linux-android21-clang.cmd'
ar = '...\llvm-ar.exe'
```

**另一个坑**：NDK 的 bin 目录里，

| 文件 | 类型 | Windows 可用？ |
|---|---|---|
| `aarch64-linux-android21-clang` | shell 脚本（`#!/u`） | ❌ |
| `aarch64-linux-android21-clang.cmd` | cmd 批处理（`@ech`） | ✅ |
| `clang.exe` | PE 可执行（`MZ`） | ✅ |

**必须用带 `.cmd` 的**，无扩展名那个是给 MSYS 用的 shell 脚本。

> 注：主工程走 `tauri android build` 时，Tauri 的 rust gradle 插件会自己配这些，
> 不需要手写。这份配置只服务于脱离 Tauri 的独立验证。

### 7.3 中文路径：只靠 `CARGO_TARGET_DIR` 绕开

仓库根是 `F:\工作记录本`（中文）。NDK 的 linker wrapper 会把非 ASCII 路径按系统
ANSI 代码页转码 —— `工作记录本` 会变成 `\xb9\xa4\xd7\xf7\xbc\xc7\xc2\xbc\xb1\xbe`，
路径就废了。解法是把 target 目录指到纯英文路径：

```
CARGO_TARGET_DIR=C:\Android\wl-target
```

⚠️ **这一条绝对不能设成全局环境变量。** 桌面版打包路径写死了仓库根的
`target/release/worklog.exe`（见 README 的打包段），全局设了会把桌面产物也挪到
`C:\Android\wl-target`，打包步骤就找不到文件了。

所以它只写在 `android/tools/with_android_env.py` 里，**只对安卓构建生效**。

### 7.5 为了能装机验证，顺手签了个调试包

产出的是 `-unsigned.apk`，装不上手机。为了能真装一次看骨架自检页，
用标准调试密钥签了一份（**这不是正式签名，阶段 5 才做正式 keystore**）：

```
WorkLuLu-安卓版-0.1.0-release-arm64-阶段0.apk   5,494,984 字节 = 5.24 MB
MD5 9de4e159bb3f98b181b65f219aaef8fb
```

```bash
export JAVA_HOME="C:\Android\jdk\jdk-17.0.20+8"
BT=/c/Android/Sdk/build-tools/37.0.0
# 1. 造标准调试密钥库（AGP 也认它，之后 debug 构建会自动用）
"$JAVA_HOME/bin/keytool" -genkeypair -keystore ~/.android/debug.keystore \
  -storepass android -keypass android -alias androiddebugkey \
  -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Android Debug,O=Android,C=US"
# 2. 签（v2+v3）
"$BT/apksigner.bat" sign --ks ~/.android/debug.keystore \
  --ks-pass pass:android --key-pass pass:android --ks-key-alias androiddebugkey \
  --out <输出.apk> <unsigned.apk>
# 3. 验
"$BT/apksigner.bat" verify --print-certs -v <输出.apk>
```

⚠️ **旧的那份 `WorkLuLu-安卓版-0.1.0-release-arm64.apk` 用的是旧机器上的密钥，
那个 keystore 已经随着旧机器没了**（本次在 `~/.android`、`C:\Android`、仓库、
桌面/文档/下载里都翻过，没有）。所以：

- 新包和旧包的签名**不是同一把钥匙**，手机上装过 0.1.0 的话**覆盖安装会失败，得先卸载**。
- 正式发版前（阶段 5）必须重新生成一把 release keystore **并单独备份** ——
  丢了就没法给已装用户升级，这条实施方案里已经写了。

### 7.6 两个"看不见"的坑（排查方法比结论有用）

**坑 A：把构建输出管道给 `tail` 之后，构建过程完全不可见。**
第一次跑就是 `... 2>&1 | tail -70`，于是十几分钟里一个字节的输出都拿不到，
完全分不清是"在跑"还是"卡死"。**判断办法是看依赖缓存的体积增长**：

```bash
du -sm ~/.gradle/caches/modules-2        # 修复前 15 分钟稳定在 76 MB；修复后 90 秒到 229 MB
```

**坑 B：`cargo tauri android build` 的 `--` 后面跟的参数是给 `cargo` 的，不是给 Gradle 的。**

```bash
cargo tauri android build --apk --target aarch64 --ci -- --info
# error: unexpected argument '--info' found
#   → 它把 --info 拼进了 cargo build 的命令行
```

`--help` 里写的是"passed to the runner"，但这里的 runner 是 `cargo build`。
想调 Gradle 的日志级别只能走 `GRADLE_OPTS`：

```bash
GRADLE_OPTS="-Dorg.gradle.logging.level=info" cargo tauri android build ...
```

### 7.7 新增的两个工具脚本

| 脚本 | 作用 |
|---|---|
| `android/tools/with_android_env.py` | 带上安卓全套环境变量（含**只在这里生效**的 `CARGO_TARGET_DIR`）跑任意命令。`--print` 可以看它设了什么。 |
| `android/tools/fix_gradle.py` | 修 `gen/android` 里三处网络相关配置：`google()` 换地址、**阿里云镜像插到最前**、wrapper 补 `networkTimeout`。幂等，`--dry` 可预览。**跑完 `tauri android init` 必须跑一遍**。 |

> 顺带一个 Gradle 小坑：本机 **Kotlin 守护进程起不来**，日志里会有
> `Using fallback strategy: Compile without Kotlin daemon`。这是**警告不是错误**，
> 它会自动改成进程内编译，慢一点但结果一样。别被吓到。
